# 全地形协同机器人视觉模块 —— 物体分类系统

本项目是我参加 **“全地形协同机器人”** 比赛中的视觉处理子系统。该模块独立完成从数据采集到模型部署的全流程，最终通过串口将识别结果发送给主控 Arduino UNO，实现机器人对不同形状物体的智能分拣与响应。

---

## 📌 项目简介

- **比赛任务**：全地形协同机器人需在复杂地形中自主识别并搬运指定物体。视觉模块负责实时检测前方物体的形状类别。
- **核心功能**：识别 **三角柱**、**圆柱**、**正方体** 三种目标物体，并将分类结果通过 UART 串口发送至 Arduino UNO，供决策系统使用。
- **硬件平台**：选用 **MaixCAM‑Pro**（选型原因详见下文）。
- **开发流程**：独立完成数据集采集 → 数据筛选与清洗 → 标注 → 云端训练（MaixHub）→ 模型部署 → 串口通信实现。

---

## 🧠 分类模型

- **模型类型**：图像分类模型（基于 MobileNetV2 轻量架构，量化为 int8，适配边缘设备）。
- **训练平台**：MaixHub 在线训练服务（使用迁移学习，训练轮次 16，批量大小 32）。
- **输入尺寸**：224 × 224 × 3（RGB）
- **输出尺寸**：1 × 1 × 3（三类概率）
- **模型参数量**：2,227,715 个参数
- **数据归一化**：均值 `123.5`，标准差 `58.395`（训练时使用）
- **输出类别映射**（与 `labels` 顺序一致）：
  - `0` → `cube`（正方体）
  - `1` → `tri`（三角柱）
  - `2` → `cir`（圆柱）
- **模型文件**：
  - `model_275071.cvimodel` —— 编译后的可执行模型文件（KPU 格式）
  - `model_275071.mud` —— 模型元数据描述文件（含类别标签、输入尺寸、量化参数等）

## 🔧 硬件与通信

| 组件          | 型号/说明                          |
|---------------|-----------------------------------|
| 视觉处理单元  | MaixCAM‑Pro                        |
| 主控          | Arduino UNO                       |
| 通信接口      | UART 串口（TTL 电平，波特率 115200，8N1）|
| 识别结果发送  | 发送类别 ID（0/1/2）及置信度（可选）|

注意：此处接口需要加上电平转换模块实现3.3V-5.0V的跃迁，不然只能单向通信！！！

### ✅ 选用 MaixCAM‑Pro 的原因

- 内置 **KPU** 神经网络加速器，在 300MHz 下推理速度可达 30 FPS，满足实时性需求；
- 与 **MaixHub** 平台深度集成，支持一键训练、编译、部署，极大缩短开发周期；
- 支持 MicroPython 和 C 开发，代码移植方便，社区提供丰富例程；
- 板载 2.4 英寸 LCD 和 DVP 摄像头接口，方便现场调试与结果可视化；
- 功耗低（< 1.5W），适合电池供电的移动机器人场景。

## 📁 数据集制作（）

所有样本数据均由本人独立采集，流程如下：

- **采集**：在赛道的不同光照条件下，以俯视、侧视、斜视多角度拍摄三种物体各 800+ 张，共 2400+ 张原始图片。
- **筛选**：剔除运动模糊、曝光过度、遮挡面积 > 30% 的图像，保留约 1500 张有效样本。
- **标注**：使用 MaixHub 在线标注工具，为每张图片打上对应类别标签，并按 9:1 划分为训练集和验证集。

## 🏆 识别成果与项目经验

### 成果概述

在比赛现场经过多轮不同光照条件下的实测验证，本视觉模块对三种目标物体（正方体、三角柱、圆柱）的综合识别成功率稳定在 **90% 以上**，在实际比赛中表现出色，有效支撑了机器人的自主分拣与投掷任务。最终本项目作为视觉子系统的核心组成部分，助力团队在 **“全地形协同机器人”** 比赛中荣获 **省级二等奖**。

---

### 问题发现与迭代优化

在实际部署与测试过程中，团队发现并解决了以下关键问题，经过多轮模型迭代，显著提升了系统的鲁棒性与准确性：

#### 问题一：三角柱与正方体误识别

- **现象**：在特定俯仰角度下，三角柱的正面投影轮廓与正方体极为相似，尤其是仅呈现单一面时，模型容易产生混淆。
- **根因分析**：数据集采集时部分三角柱样本的拍摄角度过于单一，导致模型学习到了“高度近似”的特征，而非结构性的判别特征。
- **解决方案**：
  1. **数据清洗**：剔除那些在特定俯仰角度下容易产生歧义的干扰样本，减少特征重叠；
  2. **数据增强**：重新补充多角度、多姿态的三角柱图像，丰富其轮廓特征，帮助模型学习更本质的几何结构差异。

经过上述优化后，三角柱与正方体之间的误识别率显著下降。

#### 问题二：夹子背景干扰

- **现象**：当机器人使用夹爪抓取或操作物块时，夹爪会出现在画面中，对模型的识别造成严重干扰。
- **解决方案**：在后续训练轮次中，**专门增加了大量包含夹爪背景的样本图片**，让模型学会将夹爪视为“背景噪声”而非目标物体的特征。这一改进极大地提升了实际作业场景下的识别稳定性。

#### 问题三：三角柱置信度偏低

- **现象**：相比圆柱和正方体，模型对三角柱的输出置信度普遍偏低，偶尔会低于预设阈值导致漏识别。
- **解决方案**：综合考虑比赛周期紧、重新训练成本高，以及任务场景中仅有三类目标物体这三个因素，采取了一个 **实用性的策略调整**——将置信度较低的识别结果默认判定为“三角柱”。这一调整虽不完美，但在当前封闭场景下有效保证了三个类别都能被稳定输出，避免了因置信度不足造成的识别缺失。

### 盒子定位的方案取舍

比赛任务要求机器人将物块精准投递到三个不同的目标盒子中。初期方案为使用本视觉模块直接识别盒子的形状或位置，但在实际测试中发现以下瓶颈：

- **物理限制**：摄像头安装俯仰角度受限，无法同时兼顾物块和盒子的清晰成像；
- **距离约束**：小车与盒子之间可用间隔较短，强行靠近容易撞倒盒子；
- **俯视视角下的变形**：盒子在俯视图中的 2D 投影发生畸变，单纯依赖分类模型难以准确定位。

为解决上述问题，曾尝试引入 OpenCV 视觉识别方案，但该方案在实际测试中暴露出两个严重问题：

1. **资源竞争**：目标检测算法占用了大量 CPU/内存资源，导致主分类任务（三物体识别）的推理速度显著下降；
2. **模式切换开销**：在“物块识别”与“盒子定位”两种模式间切换时，不仅增加了代码复杂度，还额外消耗了电量，同时引入了不可控的时序风险。

**最终决策**：为确保比赛稳定性，决定 **暂时放弃视觉盒子定位方案**，改为 **超声波定位** 方式控制小车与盒子之间的距离。通过多次预标定测试，结合超声波的静默状态检测，使小车在固定场景下能够精准停靠在盒子前方。该方案在盒子位置固定的标准 SOP 流程中表现稳定可靠，但若盒子位置发生变动，仍需要依靠视觉方案进行适应——这也是后续升级的重要方向。
