# 全地形协同机器人 · 端侧边缘 AI 视觉感知与决策系统

> 本项目作为全地形协同机器人竞赛（省级二等奖）的视觉核心子系统，由本人**独立完成**从数据集构建、模型训练、边缘端推理部署，到上位机与下位机（Arduino）异构通信的全链路开发。

---

## 📌 项目架构与技术选型

- **核心功能**：识别赛道上正方体（cube）、三角柱（tri）、圆柱（cir）三种目标物，并将识别结果通过 UART 实时下发至下位机。
- **视觉主控**：**Sipeed MaixCAM-Pro**（内置 KPU 神经网络加速器，推理速度约 30 FPS）。
- **下位机主控**：**Arduino UNO**（执行循迹、机械臂夹取等动作）。
- **通信链路**：UART 串口，使用**电平转换模块**解决 3.3V 与 5V 异构设备的单/双向通信瓶颈。
- **设计范式**：**边缘算力解耦**——视觉算力完全下沉至 MaixCAM，下位机仅接收轻量级离散指令（`0/1/2`），极大降低主控芯片负载。

---

## 🧠 数据集构建与模型优化

- **数据采集**：独立完成采集，涵盖俯视、侧视、斜视多角度及不同光线，共获取 2400+ 张原始图片；经过去重、去模糊及剔除高遮挡后，保留 **2000 张** 有效数据集。
- **模型选型与部署**：基于轻量级分类网络（约 **222 万参数量**，量化 int8）进行迁移学习。使用 MaixHub 平台一键编译部署至 `.kmodel` 格式。
- **典型训练指标**：经过 16 Epoch 训练，最终验证集准确率 `1.0`，验证损失 `1e-05`。

> 💡 **面试/项目亮点**：模型在训练集上虽然表现出轻微过拟合特征（100% 准确率），但实际测试依然实用。我坚持 **“工程落地优于学术指标”** 的原则，摒弃了物理上不合规的数据增强（如横放三棱柱），转而通过下列工程策略保证实战效果。

---

## 🛠️ 核心工程优化策略（实战闭环能力）

### 1. 帧间多帧多数表决（抗环境噪声与抖动）
比赛场地存在震动和光线微小波动，单帧推理极易产生偶然误判。我在应用层构建了**滑动窗口机制**，连续累积 10-15 帧的推理结果，统计类别**置信度众数**。只有当绝大多数帧输出同一类别时，才向下位机发送控制指令，有效过滤了偶发的瞬间噪声，使视觉系统稳定性显著提升。

### 2. 应用层指令冗余下发（低成本抗丢包）
由于使用了非原生的电平转换模块，通信过程中偶尔会出现数据包丢失。为了保证高可靠性（不引入复杂的硬件握手机制），我采用了**极简的指令冗余策略**：单次决策通过串口发送时，**连续重复下发该指令 10~20 次**。以极低的 CPU 占用代价，成功实现了零丢包，彻底解决了下位机状态机卡死的问题。

### 3. 多维度兜底分类逻辑（闭环防误判）
- **置信度阈值裁剪**：当所有类别的置信度低于 `0.78` 时，直接输出“无法识别/拒识”信号，防止小车乱抓。
- **三棱柱置信度偏低的特殊兜底**：实测发现三棱柱（tri）在部分角度下置信度会徘徊在 `0.75~0.85` 之间。考虑到场上只有三个类别，我在代码中设定了 **“非高置信度情况下默认归类为 tri”** 的决策逻辑，确保比赛任务不间断执行。

---

## 🚧 设计局限与取舍（盒子定位的让步）

在项目初期，曾尝试复用视觉模块实现**盒子形状的定位与投掷匹配**，但这受限于两个核心瓶颈：
1. **物理视场限制**：摄像头固定在夹爪上方，视角只能俯视，无法同时兼顾物块与盒子的清晰成像，且物体在俯视图下的 2D 投影极易畸变。
2. **算力与模式切换开销**：若采用 OpenCV 或 YOLO 做目标检测，会严重抢占分类模型运行所需的系统算力资源，导致视觉主任务出现卡顿。

**最终决策**：为确保比赛整体流程的稳定性，**战略性放弃视觉盒子定位**。改为通过**超声波模块**预先标定停车点，由超声波静默状态触发放置动作。这一选择虽然降低了场景的泛化性，但十分契合“工程必须为落地让路”的思考维度，是当前资源和时间约束下的最佳系统级解决方案。
